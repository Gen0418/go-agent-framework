# GUI 功能开发路线

本文记录 `internal/interaction/gui` 接下来的开发顺序、每阶段目标以及涉及的跨层边界要点。

## 当前基线

- 已完成 `internal/interaction/gui` 的初步结构整理（`types.go` 状态定义 + `window.go` 视图与动作）。
- 已具备：侧边栏会话列表切换、按会话隔离的 `sessionState`、历史消息懒加载、后台异步 `RunTurn` 与流式输出刷新、可折叠思考块。

---

## 开发顺序

### 1. 工具调用确认

- **目标**：实现 `submit` 中的 `confirmFunc`，在模型请求执行 `bash` 等工具时展示目标目录与完整命令，等待用户允许或拒绝后再继续当前轮次。
- **关键要点**：
  - 后台 `AgentLoop` goroutine 与 UI 线程解耦（例如在 `sessionState` 维护待确认状态与结果通道），同时监听 `ctx.Done()`，避免取消或关闭窗口时阻塞泄漏。
  - 兼顾多会话切换：某会话等待确认时切去其他会话不应丢失状态，切回后仍可继续确认。
  - 顺带评估实时流中 `ToolCalls` 的展示（当前仅历史重载可见）。

### 2. 新建会话

- **目标**：提供新建会话入口，解决空库启动停留在“暂无会话”的问题。
- **关键要点**：
  - 写入 `storage.CreateSession` 后同步更新内存中的 `sessions.list`、切换选中态并初始化对应 `sessionState`。
  - 确定默认标题策略（如默认标题或后续结合首条消息/重命名调整）。

### 3. 会话内停止按钮

- **目标**：支持随时中止当前会话正在进行的模型流式输出、工具执行或待确认状态。
- **关键要点**：
  - 接通 `sessionState.cancel`（单轮/会话级）与 `app.cancel`（应用关闭时收口）。
  - 会话运行期间提交区提供明确的“停止”交互并防止重复提交；区分主动取消与真实错误提示。

### 4. 会话内 `opts` 控件

- **目标**：将 `sessionState.opts`（`Thinking`、`ReasoningEffort`、启用工具等）暴露为会话内可调控件。
- **关键要点**：
  - 当前 `AgentLoop` 在创建时持有 `opts` 值拷贝，需要明确会话内修改 `opts` 后如何同步给已绑定的 `AgentLoop`（以及是否仅对下一轮请求生效）。
  - 明确新建会话从 `app.defaultOpts` 继承默认值的行为。

### 5. 会话删除与重命名

- **目标**：支持在侧边栏对已有会话进行重命名和删除。
- **关键要点**：
  - `storage` 层补齐会话标题更新与会话删除接口（删除会话时同步清理关联 `messages`、`api_calls` 数据，保持一致性）。
  - 删除正在运行的会话前需先取消对应 `sessionState.cancel` 并清理 `sessionStates` 缓存；删除当前选中会话后需合理回退选中项（相邻会话或空态）。

### 6. 应用级 `cfg` 控件

- **目标**：支持在 GUI 中查看和调整应用级配置（`Endpoint`、`DefaultModel`、`APIKey` 等）。
- **关键要点**：
  - 明确配置更新后对已有 `AgentLoop` 与新建 `AgentLoop` 的生效范围，以及是否写回本地配置（如 `.env` 或独立本地配置文件）。
  - 界面展示与存储严格避免明文泄露 `APIKey` 到日志、数据库或 Git 跟踪文件。

### 7. 整体边界拆分和重构

- **目标**：在主要功能齐备后，整理 `gui`、`agent`、`cli`、`storage` 之间的职责边界与代码组织，补齐测试覆盖。
- **重点方向**：
  - **输出事件契约统一**：评估将 `AgentLoop` 的流式回调升级为结构化事件，补齐实时 `ToolCalls` 通知；将思考与正文间的 `splitMark = "\n"` 等展示细节下沉到 `cli` 层，确保 GUI 实时流与历史重载一致。
  - **GUI 状态与视图解耦**：将 `sessionState` / `app` 状态流转与 `mygo` 视图渲染分层，便于编写不依赖窗口的单元测试并运行 `go test -race`。
  - **边界状态收口**：统一处理历史加载失败后的提交拦截、窗口关闭时的并发清理等边界场景。

### 8. GUI 样式和效果

- **目标**：在功能和架构稳定后集中打磨界面视觉与交互体验。
- **重点方向**：
  - 整体布局、留白、字体层级与配色（侧边栏选中态、消息气泡/分区、错误提示、确认弹窗样式）。
  - 交互细节：流式输出自动滚底与手动上滑打断、长文本与代码/命令输出可读性、按钮禁用态与运行中状态反馈。
